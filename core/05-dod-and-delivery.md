# 05 DoD 四步（三态）· evidence · 交付单

> **何时读**：刹车 8 问未命中或被放行之后。
> **输出**：DoD 三态计数 + evidence summary + 交付单 → 进 [06 retro 触发判定](06-retro.md)。

## 1. 每一步的结果只有三态

> **治的是什么**：只有「过 / 不过」两格时，「没跑」无处安放 —— 要么被写成「通过」，要么当成阻断硬撑。两种都是刹车 Q5 最常见的绕法。第三格把「没跑」变成可以如实写出来、由人决定收不收的合法状态。

| 态 | 定义 | 去向 |
|---|---|---|
| ✅ 通过 | **跑了**，结果符合 done_criteria | 下一步 |
| ❌ 不过 | **跑了**，结果不符 | §3 同 goal 重做 |
| ⚪ 未验证 | **没跑**，且原因属于闭集 | 带进 evidence；写进交付单第三栏；**由用户决定收不收** |

**⚪ 的原因闭集**（只认四种）：(a) 环境 / 依赖缺（无密钥、无网、无数据、无权限、目标不可达）；(b) 成本超预算（token / 时间 / 费用到上限 —— **必须先按 [04 §3](04-brake.md)「到上限不自行免判」上升**，⚪ 是上升之后的书面形态）；(c) 上游未就绪；(d) 用户明示跳过（引用那句话）。

**三条边界**：能跑而没跑 = 盲跑，不是 ⚪ → Q5 停；跑了红 = ❌，不是 ⚪；⚪ 不算过也不算阻断 —— 带 ⚪ 可交付，但任何汇总里**不得出现「全部通过 / 全绿 / all pass」**，goal 标 `done-unverified` 而非 `done`。

**进 DoD 前先重跑路由器**（[01 §5](01-entry-and-routing.md) 第二运行点）：真 diff + 同样的 H1–H3，算出的档位高于入口 → 自动升档，补齐新档位矩阵要求的步骤再进四步；卡上 ⚠ 反查警告（声明「否」但 diff 有迹象）必须逐条回应。档位矩阵说不用做的写「**本档不要求**」，不进三态计数、不进第三栏。

## 2. DoD 四步

**① Code Review**（self-review 必做；触及 `{{paths.l}}` / `{{paths.m}}` 必走 PR review）。视角：北极星（未引入「假装是决策」的逻辑）；稳定性（未破坏已完成节点、fallback 完整、不会让整跑崩）；契约（未突破 `{{contracts}}`）；**测试设计质量**（每条测试无条件 assert；mock 不会让 pass 变成假的；不存在「防御性 guard 实为隐式 skip」）。输出 review notes。

**② Corner Case**：跑该段全部 case，不删不 skip；失败优先修主路径 / 修 fallback；改 case 走 [04 §3](04-brake.md) 四要素并升级人工；新发现的 case 回填。输出 case 表快照 + 新增列表。

**③ 冒烟**：`{{verify.smoke}}`；对照 `{{budget.latency}}` / `{{budget.fallback_ratio}}`。输出归档路径 + 关键指标。S 档本档不要求。

**④ 彻底跑通**：任一项失败修完再继续；任何「known issue 先 skip」必须登记为 deferred 项并标计划时机，**不允许沉默 skip**。

**⑤ 临时脚本处置**（四步后、evidence 前）：项目根 / tests 下不得残留 `test_quick*` / `test_tmp*` / `debug_*` / `tmp_*` / `scratch_*` 之类。有沉淀价值转正进正式测试；一次性删除；不允许「留下次再说」。

## 3. 失败处理

- 任一 ❌ → 回 [03](03-execute-and-verify.md) 同 goal 重做；重做过程**不允许降低 DoD 标准**（Q5）。
- 重做 1–2 次正常；**≥ 3 次** → 升级为「拆解有问题」，回 [02](02-decompose.md) 重拆。
- **无 ❌**（全 ✅，或 ✅ + ⚪）→ 进 §4。

## 4. evidence（M / L 档）

| 类型 | 来源 | 落地 |
|---|---|---|
| Review notes | ① | PR 描述 |
| Corner case logs | ② | 测试输出片段 / 日志路径 |
| Smoke run logs | ③ | `{{observations_dir}}` 下归档路径 |
| Archive replay | `{{archive_replay}}` | 回放日志；不动 schema 写 `N/A + 理由` |
| 改 case 证据 | ② 四要素 | PR 描述 |

**动作**：收集路径 → **验证路径真实存在**（防盲跑）→ 生成 summary：

```markdown
## Evidence Summary (goal <goal-id>)
- Review notes: <path>
- Corner case logs: <path>
- Smoke archive: <path 或 本档不要求 或 N/A(⚪ 见交付单)>
- Archive replay: <path 或 N/A + 理由>
- Modified cases: <count>
- 裁决回填清单: <§4.1，无裁决落地写 N/A>
- DoD 三态计数: ✅ a / ❌ 0 / ⚪ c   ← c 与交付单第三栏条数必须相等
- 交付单: 见 §5
```

任一应有 evidence 缺失 → 不进 retro，回 §2 补。显式 N/A 必须有理由。承重口径改动所依据的回放 / 探针，脚本与输出落一份到 `{{observations_dir}}`，不只写进 PR 描述（合并后难检索、数字无法复算）。

### 4.1 裁决落地 → 回填清单

**何时**：本 goal 定了、改了、或明确不改任何阈值 / 判据 / 触发条件；立了、关了、降档了任何账本条目或观察点；改了任何「以后按这个口径办」的说法。

**动作**：逐格过，每格「改了 <链接>」或「N/A + 一句理由」，**不许留空**：

| # | 候选真值源 |
|---|---|
| 1 | 裁决自己那条账本条目的正文（最容易漏的一格，放第一） |
| 2 | `{{backlog_file}}` 里引用该结论的其它条目 |
| 3 | 跑批与操作指南 |
| 4 | 验收判据表 `{{acceptance_standard}}` |
| 5 | 观察点表 `{{observation_ledger}}` |
| 6 | 代码常量与注释 / docstring |
| 7 | 路线图 `{{roadmap_file}}` 与主链路文档 |
| 8 | 持久记忆（含索引行） |

再加两道：**宽 grep 全仓扫**（关键词含别名与旧框架词）；**分 live 与历史** —— live 就地改口径，历史加前向一句正文不动，**冻结档连 banner 都不加**（[04 §4](04-brake.md)）；收口后再 grep 一遍确认旧措辞清零。

任一格既没改也没写 N/A 理由 → 视同 evidence 缺失。本节只要求「点名 + 交代」，写 N/A 完全正当，**空着不是**。

## 5. 交付单（固定三栏 · 所有档位）

> **治的是什么**：「未验证」规则散在三处（到上限不免判 / 没跑 review 显式写 / 报全绿附成立条件）靠记，记不住就退化成一句「全部通过」。固定格式本身就是提醒。

**何时用**：每个 goal 的最终汇报、每个 PR 描述、任何「做完了」的对话收尾。三栏都要有，顺序不变。

```markdown
## 交付单 (goal <goal-id>)
档位: <S/M/L（入口）→ <同或升档>（DoD 重算）｜事实: <路由卡第一行>>
H1 新增能力: 是/否  H2 外部副作用: 是/否  H3 不可逆: 是/否

### 改了什么
- <文件或模块>：<一句话>

### 验证了什么、怎么验的
- <验证项>：<命令 / 手段> → <结果>   ← 报「0 问题 / 全绿」必附成立条件（扫了多少对象、凭什么是全集）

### 未验证什么、为什么
- <项> ⚪：原因 (a)/(b)/(c)/(d) + 一句说明 → 建议处置（等环境 / 请用户跑 / defer 到 <条目>）
（没有就写：无）
```

**五条硬规则**：

1. 第三栏不许空白；没有就写「无」。空白 = evidence 缺失。
2. 第三栏条数 = DoD 三态表的 ⚪ 计数。不等 = 有一条被藏或被凑，不许交付。
3. 第三栏每条只能用 §1 四种原因。写不进的回去重看：多半是盲跑或跑了红。
4. 第三栏非「无」时，全文不得出现「全部通过 / 全绿 / all pass」。第二栏可逐项 ✅，不许给总评。
5. 路由卡必贴（至少档位行 + H1–H3 行）。S 档的交付单就是它全部的 evidence；卡缺失视同第三栏空白。

**为什么是格式不是再加一条规则**：格式让「没写第三栏」一眼可见，审的人不用记规则也能问一句「第三栏呢」。

## 6. 输出

evidence summary + 交付单 → 进 [06 §1](06-retro.md) 六条触发判定。
