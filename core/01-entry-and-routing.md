# 01 任务进入 · 定档（事实推档位）· 路由

> **何时读**：拿到任何新指令时。这是主链路第一步，也是唯一一份「每个任务都读」的骨架文档。
> **输出**：一张路由卡（档位 + 事实 + 三个人声明 + 必做 / 不要求 + 验证命令 + 停止条件）→ 决定后面走哪些步骤。
> **v2（2026-09-29 七点裁定）**：档位不再由「是不是大任务」「风不风险」两轮判断推出，由**事实**推出。能机检的全部机检，人只答三个是非题。v1 的「大任务七条 / 风险五条」已并入 §2 事实表与 §2.2 人声明，不再是独立步骤。

## 0. 接入片段（复制进 `{{project.instructions_file}}`）

```markdown
## 过程规则（真值源 core/，按阶段只读对应文档，不通读；参数在 project-config.md）

1. 接到任务先跑路由器出路由卡（core/01）：给「预计改动清单」+ 三个是非题（新增能力 / 外部副作用 / 不可逆操作，各一句理由）。档位 S / M / L 由事实推出，不由我判。路由卡贴在 goal 头部；只许升不许自己降；DoD 前用真 diff 重跑，升了就补步骤。L 档先给我拆解方案，我确认后再动手。
2. 按路由卡的「必做 / 本档不要求」做（core/01 §4）。S = 执行 → 自验 → 8 问 → 简版 DoD → 交付单；M = 拆成 `<goal>`（单 goal 可用路由卡代替 scope / verification）+ 全 DoD + 5 类 evidence；L = M 全部 + 用户确认 + 节点复盘 + 完整 PR。不要求的写「本档不要求」，要求但没跑的才是 ⚪。
3. 每个 goal 做完按序：跑 verification + 自验报告（core/03）→ 刹车 8 问（core/04，任一「是 / 不确定」停下问我）→ DoD 四步（core/05）→ evidence。
4. DoD 每步只有三态 ✅ / ❌ / ⚪。没跑必须标 ⚪ 并写四种原因之一；能跑没跑是盲跑。有 ❌ 不许交付；有 ⚪ 可以交付，收不收我定。
5. 交付一律三栏交付单（core/05 §5）：改了什么 / 验证了什么、怎么验的 / 未验证什么、为什么。第三栏没有写「无」，不许空着；非「无」时全文不许写「全部通过」。
6. 红线（project-config `red_lines`，以及项目指令文件里另列的红线）任何时刻触到立即停，不等任何判定。
7. goal 有返工、触发过刹车、暴露过意外坑、改过 case、属 L 档 —— 任一为真跑 goal 级 retro（core/06），否则跳过。
8. 节点收口：retro 5 问（core/06 §2）→ PR 描述按 core/07 模板。
9. 踩到坑先查坑表（project-config `pitfall_table`）；新坑回填坑表并写「路径:」字段，让路由器下次自动命中；不是加新流程。
```

## 1. 任务进入：识别类型

**输入**：用户即时指令 / `{{roadmap_file}}` 里的待办节点 / 上一节点收口后的解锁。

- 路线图节点 → 标定节点 ID。
- 临时指令 → 看是否在骨架适用范围内；**生产事故 / 热修不走本骨架**，按即时指令处理。
- 指令模糊（「看看代码」）→ 不进主链路，按聊天处理。
- 识别不出 → 停下问。

任务类型定了就进 §2，**没有「是不是大任务」这一问**。

## 2. 事实（路由器的输入）

> **治的是什么**：v1 先判「大任务」再判「风险」再判 S 判据，三轮里两轮是感觉题（「新增能力而非单点修复」「10 分钟内能否完成」），正是「自己给自己开闸」的入口。v2 把能量的全量、不能量的压成三个是非题，档位由规则表推出，执行者不判档。

### 2.1 机器提取（`{{tier.router}}` 从预计清单或真 diff 算）

| 事实 | 内容 | 配置 |
|---|---|---|
| **F1 改动清单按桶** | 每个路径归一个桶：src / tests / docs / config / infra / other；另计删除数、重命名数 | `{{tier.buckets}}` |
| **F2 行数按桶** | 每桶分别计增删合计，不再一个总数 | — |
| **F3 路径命中** | **L 档路径**（schema、prompt、迁移、CI、依赖清单、`.env`、权限配置）命中即 L；**M 档路径**（fallback、路由、闸门、质检判据、配置目录）命中即至少 M。「命中」= 出现在改动清单里，不看改了几行 | `{{paths.l}}` / `{{paths.m}}` |
| **F4 坑表命中** | 坑表条目的「路径:」字段与改动路径匹配（[08 §1](08-pitfall-registry.md)）。🔴 active 命中即至少 M；命中条目的 action 直接进停止条件 | `{{pitfall_table}}` |
| **F5 新增依赖** | 依赖清单文件有改动即 L；DoD 时再查 diff 里新出现的第三方 import | `{{tier.dependency_files}}` |
| **F6 验证可得性** | 每个 src 文件按命名约定找配对测试；找不到即不满足 S | `{{tier.test_map}}` |

### 2.2 人声明（三个是非题，各配一句理由，写进路由卡）

| # | 问题 | 为「是」的典型形态 |
|---|---|---|
| **H1** 新增能力 | 新功能 / 新选项 / 新接口 / 新配置项 | 加一个 CLI flag、开一个 endpoint |
| **H2** 外部副作用 | 联网、花钱、碰生产、发消息、调第三方 | 新调一个 API、写一封邮件 |
| **H3** 不可逆操作 | 删数据、改历史、覆盖归档、破坏性 SQL | 删文件、改已合并 commit 的引用 |

这三个仍是执行者自答。兜底：DoD 时路由器用真 diff 反查明显形态（新 `add_argument`、新 `import requests`、`os.remove`、`DROP TABLE`），声明「否」但 diff 有迹象就在路由卡上标 ⚠ 请复核。只能抓一部分，剩下靠自觉；这一点写进 `{{metrics.ledger}}` 表 1 观察。

## 3. 档位规则

| 档 | 条件（任一命中） |
|---|---|
| **L 完整** | F3 L 档路径命中 / F5 新依赖 / H2 = 是 / H3 = 是 / 触及 `{{red_lines}}` / 用户点名 |
| **M 普通** | F3 M 档路径命中 / 任一桶超 S 上限 / 跨顶层目录 / F4 🔴 active 命中 / F6 任一 src 文件无配对测试 / H1 = 是 / 有删除或重命名 |
| **S 小修** | 以上全不命中 |

**S 上限按桶分开**（`{{tier.s_limits}}`，全部试用初值，按 `{{tier.metrics}}` 季度调）：

| 桶 | S 上限 |
|---|---|
| src | ≤ 3 文件、≤ 100 行 |
| tests | ≤ 5 文件、≤ 300 行 |
| docs | ≤ 5 文件、行数不限 |
| config / infra | 任何改动都不是 S |
| 删除 / 重命名 | 任何一个都不是 S |

「同一顶层目录」按 `{{tier.same_dir_rule}}`（src 与配对的 tests 算同一处）。

## 4. 路由：每档要做什么、不用做什么

路由卡直接给出「必做」与「本档不要求」两行，来源是这张矩阵：

| 步骤 | S 小修 | M 普通 | L 完整 |
|---|---|---|---|
| 01 路由卡 | ✓ | ✓ | ✓ + 用户确认拆解方案 |
| 02 pre-flight 5 问 | **不用** | ✓ | ✓ + pitfall-scout 派遣 |
| 02 拆解 `<goal>` XML | **不用**（整个任务 = 1 个隐式 goal） | ✓（**单 goal 可用路由卡代替 scope / verification**，只补目标 / 步骤 / 完成判据） | ✓ + 拆解文件落 `{{plans_dir}}` + 用户确认 |
| 03 执行 + 自验 | ✓（verification = 路由卡给的测试 + lint） | ✓ | ✓ |
| 04 刹车 8 问 | ✓ **不省** | ✓ | ✓ |
| 05 DoD 四步 | Code Review ✓ / Corner Case = 跑路由卡给的测试 / 冒烟 **本档不要求** / 彻底跑通 ✓ | 四步全 | 四步全 |
| 05 evidence | **只交交付单** | 5 类 + 交付单 | 5 类 + 交付单 + 回填清单 |
| 06 goal 级 retro | 六条触发照旧（不分档） | 同 | 同 |
| 06 节点级 retro 5 问 | **不用** | ✓ 简版（各一行，不落文件） | ✓ 完整（落 `{{retro_dir}}`） |
| 07 PR | 可不开（按 `{{autonomous_scope}}`）；开则简版 = 路由卡 + 交付单 | 完整模板 | 完整模板 + review |
| 07 cold review | 不用 | 可选 | 推荐 |
| 08 坑表 | 路由卡已按路径扫 | 同 + 起步扫相关段 | 同 + pitfall-scout 必派 |

**两种「没做」两种记法，不许混**：矩阵说不用做的写「本档不要求」；矩阵要求但没跑的才是 ⚪（[05 §1](05-dod-and-delivery.md)）。交付单第三栏只放 ⚪；路由卡必须贴在交付单头部，让审的人能核「不要求」站不站得住。

## 5. 路由卡、三个运行点、只升不降

**路由卡**（`{{tier.router}}` 输出，贴在 goal 头部，同时就是档位声明）：

```
档位: M ｜ 事实: src 2 文件 / 71 行；tests 1 文件 / 30 行；M 档路径命中 [src/app/router.py]；坑表 🔴 active 命中 §3.2-12
H1 新增能力: 是（加 --json 选项）  H2 外部副作用: 否  H3 不可逆: 否
必做: 路由卡 / pre-flight 5 问 / goal XML（单 goal 可用本卡代替 scope、verification）/ 执行 + 自验 / 刹车 8 问 / DoD 四步全 / 5 类 evidence + 交付单 / 节点级 retro 简版 / 完整 PR
本档不要求: 用户确认拆解 / pitfall-scout 派遣 / cold review
验证命令: pytest tests/test_router.py tests/test_cli.py
停止条件（来自坑表）: §3.2-12 改路由前确认 fallback 链 → grill fallback
需用户确认: 否
```

**三个运行点，同一个脚本**：

| 运行点 | 输入 | 作用 |
|---|---|---|
| **入口**（必跑） | 预计改动清单 + H1–H3 | 出路由卡；决定要不要拆解、要不要用户确认。**S / M 档也必须跑**，不然 M 的拆解决策没依据；S 档给个文件清单也就一行。H 漏答按「是」计、答非 yes/no 直接报错 |
| **DoD 前** | 真 diff + 同样的 H1–H3 | 重算。档位升了 → 列出要补的步骤，补完再进四步；降了不理会，仍按入口档位走 |
| **CI**（PR 事件） | 真 diff + PR 描述里的 H 行与档位行 | 声明档位低于算出的就报；PR 描述里没有档位行也报（= 没跑路由器就交付）。WARN 试用，`{{checks.registry}}` |

**只升不降**：

1. 路由卡的档位就是入口声明；写不出事实行的不算跑过路由器。
2. DoD 前重算升档 → 自动升档，补做新档位矩阵新增的步骤，写进卡上：`档位: S → M（DoD 重算：src 桶 4 文件 > 3）`。
3. **禁止自己降档**。唯一例外 = 用户明确说，且引用原话：`档位: M → S（用户裁：「…」）`。
4. **拿不准 → 高一档**。H1–H3 答不准的按「是」。
5. **S 档的隐式 goal 仍受停止条件**：做到一半发现要碰 L / M 档路径，那一刻就是升档信号，停下按 M / L 走，不是「顺手改完再说」。

三档只改「做多少」，**不改红线**；刹车 8 问和 retro 六条触发不分档。

## 6. 分流

- **S** → 直接进 [03](03-execute-and-verify.md)。
- **M** → [02](02-decompose.md) pre-flight + 拆解，不停。
- **L** → [02](02-decompose.md) 拆解完**停下等用户确认**，再进 [03](03-execute-and-verify.md)。
