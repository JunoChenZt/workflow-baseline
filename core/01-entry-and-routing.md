# 01 任务进入 · 风险判定 · 定档与路由

> **何时读**：拿到任何新指令时。这是主链路第一步，也是唯一一份「每个任务都读」的骨架文档。
> **输出**：任务类型 / 是否大任务 / 风险层级 / 档位 + 一行判据 → 决定后面走哪些步骤。

## 0. 接入片段（复制进 `{{project.instructions_file}}`）

```markdown
## 过程规则（真值源 core/，按阶段只读对应文档，不通读；参数在 project-config.md）

1. 接到任务先定档 S / M / L（core/01）：判是不是大任务（七条）→ 是则判风险（五条）→ 非大任务再过 S 判据五条。全满足才是 S。档位写一行进交付单头部；只许升不许自己降；DoD 前按实际 diff 对账，超了自动升档。拿不准 → 高一档。L 档先给我拆解方案，我确认后再动手。
2. 按档位矩阵（core/01 §4）做：S = 执行 → 自验 → 8 问 → 简版 DoD → 交付单；M = 拆成 `<goal>`（core/02）+ 全 DoD + 5 类 evidence；L = M 全部 + 用户确认 + 节点复盘 + 完整 PR。矩阵不要求的写「本档不要求」，要求但没跑的才是 ⚪。
3. 每个 goal 做完按序：跑 verification + 自验报告（core/03）→ 刹车 8 问（core/04，任一「是 / 不确定」停下问我）→ DoD 四步（core/05）→ evidence。
4. DoD 每步只有三态 ✅ / ❌ / ⚪。没跑必须标 ⚪ 并写四种原因之一；能跑没跑是盲跑。有 ❌ 不许交付；有 ⚪ 可以交付，收不收我定。
5. 交付一律三栏交付单（core/05 §5）：改了什么 / 验证了什么、怎么验的 / 未验证什么、为什么。第三栏没有写「无」，不许空着；非「无」时全文不许写「全部通过」。
6. 红线（project-config `red_lines`）任何时刻触到立即停，不等任何判定。
7. goal 有返工、触发过刹车、暴露过意外坑、改过 case、属高风险 —— 任一为真跑 goal 级 retro（core/06），否则跳过。
8. 节点收口：retro 5 问（core/06 §2）→ PR 描述按 core/07 模板。
9. 踩到坑先查坑表（project-config `pitfall_table`）；新坑回填坑表，不是加新流程。
```

## 1. 任务进入：识别类型 + 是否大任务

**输入**：用户即时指令 / `{{roadmap_file}}` 里的待办节点 / 上一节点收口后的解锁。

**动作**：

1. **识别任务类型**：路线图节点 → 标定节点 ID；临时指令 → 看是否在骨架适用范围内（生产事故 / 热修**不走本骨架**，按即时指令处理）；指令模糊（「看看代码」）→ 不进主链路，按聊天处理。
2. **是否大任务**：`{{big_task_triggers}}` 七条任一命中即是。
3. 识别不出类型 → 停下问：「这属于路线图节点 / 临时指令 / 别的范畴？」

**输出**：`task_type` / `is_big_task`。

## 2. 风险判定（仅大任务）

`{{risk.high_triggers}}` 五条任一为真即高风险。输出 `risk_level: high|low` + **≤ 3 行**判定理由（超过 3 行 = 判定本身有问题，回炉）。

- 不确定 → **默认高风险**，停下问。用户可推翻。
- 「五条都不触发」≠ 零风险，仍要拆解，只是免去用户确认。
- 触及 `{{red_lines}}` 的任务风险永远是高，且必须停下问，不进拆解。红线是「立即停」，风险判定是「走哪条路」，两者不互相替代。

## 3. 定档（S / M / L）

> **治的是什么**：修一个错别字按字面也要走 XML 拆解、5 类 evidence、节点复盘。流程成本与任务风险不匹配，要么被悄悄绕开（= 刹车 Q5），要么把执行者拖到不愿意用。
> **最要紧的设计点：档位由谁判。** 执行者自己判档就是「自己给自己开闸」。所以：判据客观可核；只许升不许自己降；DoD 前按实际 diff 对账。

| 档 | 定义 |
|---|---|
| **S 小修** | 非大任务，且 S 判据 **5 条全满足** |
| **M 普通** | 大任务 + 低风险；**或** 非大任务但 S 判据任一不满足 |
| **L 完整** | 大任务 + 高风险；**或** 触及 `{{red_lines}}`；**或** 用户点名 |

**S 判据**（每条都能用 `git diff --stat` 或路径核，不需要判断力）：

| # | 判据 | 怎么核 |
|---|---|---|
| 1 | 改动文件 ≤ `{{tier.s.max_files}}`，且在同一顶层目录（`{{tier.s.same_dir_rule}}`） | `git diff --stat` 数文件、看路径 |
| 2 | 增删合计 ≤ `{{tier.s.max_lines}}` 行 | `git diff --stat` 末行 |
| 3 | 不碰 `{{sensitive_paths}}` 任何一项 | diff 路径对表；「碰」= 出现在 diff 里，不看改了几行 |
| 4 | 不新增能力 / 外部依赖 / 配置项。形态限于：bugfix、typo、文档、注释、只加测试、重命名、日志文案 | 看 diff；新 import 第三方包 / 新 env 读取 / 新 CLI 选项即不满足 |
| 5 | 有现成的验证手段可立即跑（`{{verify.unit}}` / `{{verify.lint}}` 之一能覆盖） | 列出那条命令；列不出就不是 S |

判据 1、2 的数字是配置初值，按 `{{tier.metrics}}` 定期调，不凭感觉改。

**⏳ 待商量**：判据还要再细化，且可以引入程序化路由器（读 diff 与路径、输出档位与要走的步骤）。骨架把「定档」（本节）与「路由」（§4）分成两节就是为此留的接口；落地时只换 `{{tier.router}}` 的实现，流程本体不动。

## 4. 路由：每档要做什么、不用做什么

| 步骤 | S 小修 | M 普通 | L 完整 |
|---|---|---|---|
| 01 判定 + **档位声明** | ✓ 一行 | ✓ | ✓ + 用户确认拆解方案 |
| 02 pre-flight 5 问 | **不用** | ✓ | ✓ + 派坑表扫描（[08 §4](08-pitfall-registry.md)） |
| 02 拆解 `<goal>` XML | **不用**（整个任务 = 1 个隐式 goal） | ✓ | ✓ + 拆解文件落 `{{plans_dir}}` + 用户确认 |
| 03 执行 + 自验 | ✓（verification = 受影响测试 + lint） | ✓ | ✓ |
| 04 刹车 8 问 | ✓ **不省** | ✓ | ✓ |
| 05 DoD 四步 | Code Review ✓ / Corner Case = 跑受影响测试 / 冒烟 **本档不要求** / 彻底跑通 ✓ | 四步全 | 四步全 |
| 05 evidence | **只交交付单** | 5 类 + 交付单 | 5 类 + 交付单 + 回填清单 |
| 06 goal 级 retro | 六条触发照旧（不分档） | 同 | 同 |
| 06 节点级 retro 5 问 | **不用** | ✓ 简版（各一行，不落文件） | ✓ 完整（落 `{{retro_dir}}`） |
| 07 PR | 可不开（按 `{{autonomous_scope}}`）；开则简版 = 档位声明 + 交付单 | 完整模板 | 完整模板 + review |
| 07 cold review | 不用 | 可选 | 推荐 |
| 08 坑表 | 撞坑时查 | 起步时扫相关段 | 扫描必派 |

**两种「没做」两种记法，不许混**：矩阵说不用做的写「本档不要求」；矩阵要求但没跑的才是 ⚪（[05 §1](05-dod-and-delivery.md)）。交付单第三栏只放 ⚪；「本档不要求」不进第三栏，但交付单头部必须写档位，让审的人能核「不要求」站不站得住。

## 5. 只升不降 + 自动升档

1. **入口声明**：`档位: S ｜ 判据: 2 文件 / 41 行 / 无敏感路径 / bugfix / <验证命令>`。写不出五个判据值的不是 S。
2. **DoD 前对账**：`git diff --stat <base>` 数文件、数行、对 `{{sensitive_paths}}`，与入口声明比。任一超出 → **自动升档**，补做新档位矩阵新增的步骤（S → M 至少补：简版 goal 的 objective / scope / verification、完整 DoD 四步、5 类 evidence）。写进头部：`档位: S → M（DoD 对账：diff 触及 <路径>）`。
3. **禁止自己降档**。唯一例外 = 用户明确说，且引用原话：`档位: M → S（用户裁：「…」）`。
4. **拿不准 → 高一档**。
5. **S 档的隐式 goal 仍受停止条件**：做到一半发现要碰敏感路径，那一刻就是升档信号，停下按 M / L 走，不是「顺手改完再说」。

三档只改「做多少」，**不改红线**；刹车 8 问和 retro 六条触发不分档。

## 6. 分流

- **S** → 直接进 [03](03-execute-and-verify.md)。
- **M** → [02](02-decompose.md) pre-flight + 拆解，不停。
- **L** → [02](02-decompose.md) 拆解完**停下等用户确认**，再进 [03](03-execute-and-verify.md)。
