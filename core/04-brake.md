# 04 刹车自检 8 问

> **何时读**：goal 自验通过后、进 DoD 前。**不分档**：S 档省掉了拆解和 5 类 evidence，但 8 问不省，它一屏以内。
> **定位**：默认放行，触发任一即停。不是日常审批，是「goal 做完了，但可能越界」的兜底。区别于 [03 §3](03-execute-and-verify.md) 执行中硬边界（事前刹车），本文件是事后审查。

## 1. 8 问

任一答案为「是」或「不确定」→ **停下提请人工确认**，不靠「应该没问题」通过：

| # | 问题 | 边界类别 | 典型形态 |
|---|---|---|---|
| 1 | 是否可能影响生产可用性？ | 生产 | 部署 / 重启生产服务 / 改生产配置 |
| 2 | 是否可能泄露或修改敏感配置？ | 敏感配置 | 密钥 / 凭据 / 仓库设置 / 仓库可见性 |
| 3 | 是否可能改变系统的合规边界或 `{{project.north_star}}`？ | 北极星 | 项目「永不越线」那句话所指的一切 |
| 4 | 是否可能造成不可逆数据变化？ | 不可逆 | migration / 删除 / 覆盖 / 破坏性 SQL |
| 5 | 是否在降低测试、契约、fallback 或回放标准？ | 标准降低 | 跳过 DoD / 改 case / 沉默 skip / 见 §3 |
| 6 | 是否会改写已完成工作的历史记录？ | 历史改写 | 回滚已合并的 PR / 改已冻结档 / 见 §4 |
| 7 | 是否需要用户承担额外费用、外部依赖或安全风险？ | 用户成本 | 新外部服务 / 新数据源 / 限流 / 隐私 |
| 8 | 是否存在两个以上合理方案，且选择会影响后续路线？ | 路线选择 | ≥ 2 个合理方案 → 用户决定 |

Q1–Q4 的具体清单来自 `{{red_lines}}` 与 `{{confirm_before}}`；Q3 触及即是红线，无商量。

## 2. 命中 / 不命中后的动作

**命中**：保留当前代码状态（已 commit 的不回滚）→ 输出命中的问与具体描述 → 停下等裁决：**放行** → 进 [05 DoD](05-dod-and-delivery.md)；**改方向** → 回 [03](03-execute-and-verify.md) 重做 goal（不重拆）；**停** → 升级红线流程。

**不命中**：直接进 [05](05-dod-and-delivery.md)，不停。

## 3. Q5「标准降低」判定细则

Q5 是最容易被架空的一问，因为绕过它的方式都长得像正当理由。

**隐式 skip 清单**（命中任一 = Q5 命中）：

1. `if cond: assert …` —— 条件不命中时 assert 整段不跑。看到 `if` 包 `assert` 立即扣问「cond 不命中时 assert 跑不跑？」
2. mock 设计让测试看起来 pass 但实际未验证目标行为
3. `pytest.skip()` / `xfail()` 未在 PR 描述显式标 deferred
4. 测试在某些环境下条件分支跳过 assert
5. check / gate 报告只报「N/N pass」，不披露执行过程中的异常、绕过路径、意外操作 —— 以结果掩盖过程

**正确替代**：无条件 assert；用 fixture 主动制造条件；显式 skip + PR 登记 deferred；报告**必须含执行过程描述**，全程顺利也要显式声明「无异常路径」。

**改 case 必须升级人工**：仅当 case 与产品目标 / 北极星明确冲突才允许改，且 PR 描述写四要素（原文 / 原因 + 证据 / 影响范围 / 是否回填新 case）。

**两种「看似正当的理由」也是 Q5 命中**：

- **「我到上限了」**：当你怀疑某目标受限于客观上限、再努力也过不去，这本身就是 Q5 信号。**不允许**自行判定「这是上限所以不算降标准」就放行。正确动作：① 用非技术语言写明撞的是什么墙、哪些做不到 / 没验证、诚实的替代或 defer 是什么；② 上升人工裁决；③ 放行后这一项在 DoD 里标 ⚪ 原因 (b)，交付单第三栏写「原因 (b) + 裁决出处」，**不许**因放行写成 ✅（[05 §1](05-dod-and-delivery.md)）。
- **「我修的是 bug」**：修 finding 时若改动**缩小了一道用户已拍板的承重闸的覆盖面**（执法范围 / 触发集合 / 白名单收窄 / 容差放宽），即便理由是「原实现会误判」，也是 Q5 命中。判据是「这个改动缩小了谁的承重面」，不是「我的理由对不对」；理由成不成立由拍板的人判。

两者同源：执行体拿一个看似正当的理由给自己开闸。把判断权交回人，闸才不被自己架空。

## 4. Q6「历史改写」判定细则

- 包含：改主依赖大版本、跨阶段重构、修改已完成节点的核心契约或 commit 引用、回滚已合并的 PR。
- **冻结档**：已声明冻结的 verdict / 节点 retro / 已关闭的账本条目，**任何触碰**都是 Q6 命中 —— 含导航、链接、元数据、读法注解、错别字，没有「只改元数据」例外。可发现性缺口去**引用方**补（独立 ADDENDUM / 入口侧加链 / 反向索引落在引用方），不动冻结档本体。
- 与「状态切换全仓收口」的接缝：收口时分完 live / 历史后，**再问一句「这份历史是不是冻结档」**；是 → 连 banner 都不加，前向事实写去引用方。

## 5. 一句话记忆

不确定就是命中。理由再好也交给人判。放行不等于通过。
