# AG 阶段二预验：analyst prompt 共用段前置 A/B 实验

> 日期：2026-08-11 ｜ 分支：`auto/AG` ｜ 触发：[backlog AG](../../governance/backlog.md#ag-全链路-kv-cache--prompt-caching-优化2026-05-29-记录) 拆解期用户要求先验证再决定
> 关联拆解：[AG-prompt-caching-decomposition.md](../../plans/AG-prompt-caching-decomposition.md)（本实验对应其中 AG.4 / AG.5 的**前置预验**，非正式执行）

---

## 结论先行

**共用段前置带来的缓存收益 = 0，不是"小"，是机制上就不可能有。** 八个分析师是并行发出的，同时开跑、谁也没等谁 —— 第一个还没把开头写进缓存，另外七个已经在路上。缓存要生效得有先后，这里没有先后。

**据此建议：AG 阶段二（prompt 重排）放弃，不是暂缓。** 要让它有意义，前提是把八个分析师改成串行 —— 拿并发换缓存，明显划不来。

**附带质量迹象（不构成结论）**：重排后八份报告里七份正文变短、部分接近腰斩，结论分布从均衡偏向看多。单跑一对、温度 0.4，按本仓「高方差指标单跑不下结论」的规矩**只能算迹象**。但既然收益是零，无需再花钱分辨。

## 1. 实验设计

| 项 | 值 |
|---|---|
| 标的 / query | 英伟达（NVDA）中文 query |
| 跑的段 | 仅第 ② 段「并行研究（8 analyst）」 |
| 起点 | 两臂共用同一份第 ① 段产物 [seg1-context.checkpoint.json](run-NVDA-zh-20260811/seg1-context.checkpoint.json) —— 排除数据面差异 |
| 唯一变量 | [analyst/\_\_init\_\_.py](../../../src/committee/prompts/analyst/__init__.py) 的拼装顺序，八处对调；**prompt 文本一字未改**（实测每 role 前 200 字符在实验臂中完全一致 = 共用段真的到了最前面） |
| 对照臂 A | 现行顺序（角色专属段在前、共用输出格式说明在后）→ [arm-A-current-order/](arm-A-current-order/) |
| 实验臂 B | 共用段前置 → [arm-B-reordered/](arm-B-reordered/) |
| 实验后 | 代码已 `git checkout --` 复原，工作树零残留 |

**已知局限（写在前面，防日后被当强结论引用）**：单 query、单段、每臂各跑一次；温度 0.4；分析师全部跑在 deepseek（见拆解 §0.3），结论**不能外推到 Anthropic / Gemini 的缓存行为**。

## 2. 成本与缓存（主结论证据）

按两臂的分段调用日志统计：

| | 调用数 | 输入 token | 命中缓存 | 命中率 | 花费 |
|---|---|---|---|---|---|
| A 对照 | 23 | 202,959 | 58,752 | **28.9%** | $0.0618 |
| B 重排 | 24 | 222,828 | 58,496 | **26.3%** | $0.0752 |

> 口径说明：CLI 的计量表分别报 24 / 25 次（比分段调用日志各多 1 次），两处口径差未深究，不影响结论方向。花费取 CLI 计量表。

**决定性的一条 —— 各角色首次调用的命中量**：

| 角色 | A 首调 input / 命中 | B 首调 input / 命中 |
|---|---|---|
| commodity | 6,284 / **0** | 6,285 / **0** |
| economist | 7,496 / **0** | 7,497 / **0** |
| fundamentals | 7,137 / **0** | 7,138 / **0** |
| historian | 7,140 / **0** | 7,141 / **0** |
| macro | 6,286 / **0** | 6,287 / **0** |
| political | 7,243 / **0** | 7,244 / **0** |
| sentiment | 6,292 / **0** | 6,293 / **0** |
| technical | 8,540 / **0** | 8,541 / **0** |

**八个角色的首次调用，两臂命中量全部为 0，一个不差。** 共用段挪到最前面之后，跨角色共享**根本没发生**。

那 5.8 万命中来自哪里：同一个角色自己的第二、三次调用（工具循环 / 扩写）—— 那些是**串行**的，所以吃得到。两臂这个数几乎相同（58,752 vs 58,496），说明重排既没帮上忙、也没弄坏它。

### 2.1 机制解释

**⚠️ 以下为推断，由上表零命中强支持，但未做隔离实验单独证实。**

八个 analyst 节点是并行执行的（异步并发，图上是并行分支）。前缀缓存要生效必须有先后：先有一次调用把开头写进缓存，后来的才能读到。八个同时发出时，谁都不在谁之后 → 共用前缀再长也吃不到。

**可证伪的预测**：若把八个分析师改成串行，第 2–8 个的首调命中量应显著大于 0。本轮未验（拿并发换缓存不划算，不值得为验证而验证）。

## 3. 产出质量对比（迹象，非结论）

| 角色 | 要点数 A→B | 证据条数 A→B | 正文字数 A→B | 结论 A→B |
|---|---|---|---|---|
| commodity | 4 → 4 | 6 → 6 | 3253 → 2396 | 看多 → 看多 |
| economist | 5 → 6 | 8 → 6 | 1345 → **805** | 中性 → 看多 |
| fundamentals | 5 → 5 | 7 → 5 | 1395 → **764** | 看多 → 中性 |
| historian | 5 → 5 | 6 → 5 | 1790 → 1135 | 中性 → 看多 |
| macro | 4 → 5 | **0 → 6** | 1182 → 1199 | 中性 → 看多 |
| political | 5 → **3** | 7 → 7 | 1699 → 1186 | 看空 → 看空 |
| sentiment | 5 → 5 | 6 → 6 | 1339 → **713** | 中性 → 中性 |
| technical | 5 → **3** | 7 → 5 | 2020 → **2707** | 看多 → 看多 |

**两臂都是 8/8 份报告齐全、无空报告、无解析失败降级。**

观察到的方向性差异：

- **七份正文变短**（唯一变长的是 technical），其中三份接近腰斩
- **结论分布偏移**：A = 3 看多 / 4 中性 / 1 看空 → B = 5 看多 / 2 中性 / 1 看空
- 证据条数多数微降；macro 那份从 0 变 6（A 臂的 0 是已在案的老形态）

**为什么这不算结论**：单跑一对、温度 0.4，噪声地板未知（本仓规矩要求同配置 ≥2 次才能定地板）。八份同向变短确实比随机抖动更像系统性效应，但**一对样本不足以分辨**。

**为什么不再花钱分辨**：收益已确证为零，质量哪怕完全不变也没有做的理由。

| AG.2 / AG.3 贴标记 + 收口 | 不受影响；但注意本实验证明的是**并行场景**，贴标记的收益点在 fund_mgr（串行），两者不冲突 |

对拆解文档 §5「阶段二暂缓」的措辞应升级为**放弃**，理由从"收益 < $0.01/run"改为"实测为零"。

## 5. 沉淀

已回填 [已知坑表 §3.2](../../governance/workflow/09-known-pitfalls.md) 的 prompt 排序条：原规矩「共用段排最前」**只对有先后的调用成立**；并行发出的一批调用之间，共享前缀吃不到。这一条比原规矩更要紧 —— **并行正是本仓的默认写法**。
