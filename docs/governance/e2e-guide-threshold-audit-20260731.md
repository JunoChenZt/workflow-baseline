## 导读（大白话）

我们有一份九步验收清单，每跑完一段就对着它逐条打勾。这次把清单上**所有带数字的条目**拿过去，
用过去两个月真实跑过的 15 次记录量了一遍，想知道：**这些数字当初是怎么定的，现在还准不准。**

结果不太好看。清单上 12 条数字判据里：

- **2 条从来没达标过** —— 不是系统坏了，是线定得脱离现实。照章办事的话每次都得判「失败」。
- **7 条从来没失败过**，而且离及格线远得离谱。其中 2 条在设计上就**不可能**失败（另一个地方已经硬性保证了，这里再查一遍纯属装饰）。
- **1 条在 11 次里有 10 次根本无从判起** —— 要检查的那个字段本身几乎从来是空的。
- **只有 1 条真的抓到过东西。**
- **只有 1 条有过重新测量的记录**，也正好是唯一一条「紧但不空」的线。

还有一个更值得记的发现：我们特意找了 4 次**故意投毒的测试跑**（输入里塞了垃圾数据），
拿同一套数字线去量 —— **除了一条以外，其余全部指标跟正常跑分不出来**。
这说明这套清单量的是「流程有没有跑完整」，不是「内容是不是真的」。这本身不算错
（内容真伪归别的闸门管），但清单里没写明这条边界，容易让人把「全绿」读成「这跑没问题」。

## 2. 逐类展开

### 🔴 空线（照字面每次都判失败）

**#1 `audit_passed ≥ 50%`** —— BB 的立账起因。11 次实测 6%–47%，**从没有一次达标**，最高的 47% 也差着 3 个百分点。
与 audit 的既定定位自洽：audit 永久停在「来源存在性」半项（AUDIT-3CHECK 已砍），T11 又把存在性泡沫挤掉过一轮。
**在当前定位下 `audit_passed` 本就该是少数**，50% 是按早已废弃的「三检查」时代想象定的。
该行 2026-07-22 被订正过一次，但只改了字段名（`verified` → `audit_passed`）、没重估阈值——而订正当天那次 run 自己就是 6%。

**#2 辩论总 output「通常 <15k」** —— 4 次可测的 run 全部在 **22,427 / 23,492 / 24,937 / 28,361**，
**每次都超线 50%–90%**。按 guide 写法「远超 → 续写/重试问题」，等于每次都该去查续写失控，
但实际原因是结构性的：双方每轮都触发续写补足 `MIN_CHARS_DEBATE=1500`，6 轮 × 双方 = 必然堆到 20k+。
**线没跟上 `MIN_CHARS_DEBATE` 的现实。**

### 🟠 前提常年不成立（判据空过）

**#3 `entry` 非占位符 / 价位 level 存活** —— **11 次正常 run 里 10 次 `execution_plan.entry` 是 `null`**，
只有 2026-07-31 这次填了 `165.0–178.0`。

guide 自己在 2026-07-22 加过警告：「fm 填不填结构化价位是**高方差行为**（旧码同起点两跑 1:1 分裂）」。
实测比那个描述更极端：**不是 50/50，是 1/11**。这意味着 ⑨ 段的两条 D2 价位判据
（「entry 非占位符」「价位 level 是否存活 / 有没有被静默抹除」）在 **91% 的 run 里无从判起**——
判据恒真 = 空过，而不是通过。

> ⚠️ 这条比「线定错了」更麻烦：空线至少会**吵**（每次判 ❌ 有人看见），
> 空过是**静默**的 —— 打勾打了两个月，其实一次都没真验过。

### ⚪ 结构性恒真（另一处已硬性保证，此处纯装饰）

**#4 `rework_counts ≤ 2`** —— guide 自己写「>2 = 不可能（上限即 2）」。上限由 `MAX_REWORK_PER_ROLE=2` 常量保证，
checklist 再查一遍**在逻辑上不可能失败**。

**#5 `confidence ∈ [1,10]`** —— guide 自己写「schema 是 closed Literal + ge/le 约束，正常不可能越界」。同上。

> 这两条的价值不是零 —— 它们能抓「常量/schema 被人改了」这类回归。
> 但那属于**单测该管的事**，放在人工 checklist 里每段读一遍是纯开销。

**#6/#7 辩论 6 轮 / 10 voter** —— 15/15 零方差，由 graph 拓扑决定。作为「节点没崩」的存活探针有意义，
作为「质量判据」无意义。

### 🟡 钝线（方向对，但余量大到不会响）

**#8/#9/#10** —— `key_points ≥ 2`（实测最小 3）、`evidence_log ≥ 1`（实测最小 3）、`core_risks ≥ 3`（实测 3–4，从没低于 3，疑似 prompt 硬性要求 3 条）。
方向都对，只是线离现实太远，**不会在质量真的下滑时提前响**。

### 🟢 有效的两条（正面样板）

**#11 `key_claims ≥ 2`** —— **全表唯一真 fail 过的线**：`claim 最少 = 0` 出现 5 次
（06-11 那次正常 run + **全部 4 次对抗 run**）。这条既抓到过正常 run 的退化，
也是对抗 run 上**唯一**被区分出来的指标。

**#12 `query_class` input ≤ 800** —— 实测 718–729，**贴着线但没越**。
它是全表**唯一有校准记录**的线（2026-06-05 QC-R1 G2 实测后由 ≤500 上移到 ≤800，并在 guide 里写明了理由和实测值）。
唯一「紧但不空」的线出自唯一一次重新测量 —— 这不是巧合。

## 3. 元发现：这套线对「输入被投毒」零判别力

拿 4 次 [r5 垃圾注入](../observations/r5-garbage-injection-2026-06-12/) 的对抗 run（**已知坏输入**）跑同一套线：

| | 报告 | 辩论轮 | 票 | facts | audit% | core_risks | 决策 |
|---|---|---|---|---|---|---|---|
| 对抗 run ×4 | 8/8 | 6 | 10 | 30 | 7% | 3 | SELL |
| 正常 run 区间 | 7–8/8 | 6 | 10 | 30–76 | 6–47% | 3–4 | HOLD/SELL |

**除了 `key_claims`（对抗 run 全 0），其余每一项都落在正常 run 的区间里、分不出来。**

这不等于 checklist 没用 —— 它量的是**形态完整性**（节点有没有跑、产出有没有形状），
内容真伪归 audit / 打码门 / quality gate 管，分工本身合理。
**但 guide 没写明这条边界**，读者容易把「段间全绿」读成「这跑没问题」。
2026-07-31 那次跑就是现成例子：段间 ①–⑨ 全过、quality gate 13/0/0，
而辩论正文里躺着 5 个**编造的引用锚**，全程没有任何一条数字线看得见它。

| # | 建议 | 理由 |
