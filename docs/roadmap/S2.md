# S2 — 成熟、独立、任何项目可复用

> **阶段划分**：S1 = 骨架成立 + 本仓自用（里程碑 M0、M1，2026-09-29 → 09-30）。S2 = 从「在一个仓库里自洽、能跑、有自动检查」走到「陌生项目十分钟接入、不改骨架、规则有程序层的手」。
> **验证方式**：本文档的每条目标都**在下次真实接入时测**，不在本仓里空转。**每条目标一个 GitHub issue（标题后括号里的号）：讨论在 issue，落地走 PR 并在描述里写 `closes #n`。** 接入撞出的具体活进 [backlog.md](../../backlog.md)，条目引用本文的 G 编号。
> **写法**：每条目标先说「做什么、为什么」，再给「怎么算做到」。判据要能在接入那天当场核，核不了的不写。

## 0. 导读（非技术版）

现在这套东西像一份写得很完整、也在自己身上试过两天的工作手册。它还没交到过第二个人手里。S2 要回答的只有一个问题：**换一个项目、换一个人，它还能不能用。** 为此要做五件事：找一个项目真接一次；把「填五十项配置」压成「选一套预设、填五项」；让规则不只写在纸上，工具调用前就能拦住；让骨架和它的复制品不会各说各话；跑完第一个周期，看哪些规则从没拦到过东西。

## 2. 目标

### 必须（没有它就不算成熟）

**G1 一次真实外部接入。**（#7）
做什么：找一个形状与本仓不同的仓库（有真实代码、有测试、有 CI），按 README 三步接入，做完一件真事。
为什么：所有规则到现在只在自己身上跑过；「通用」是主张不是事实。这一条会自动暴露 G2、G3、G5。
判据：C1；接入日志 `docs/observations/adoption-<repo>-<日期>.md` 记录每一处卡点；卡点逐条进 backlog。
顺序：**第一个做**。

**G2 项目形状预设。**（#8）
做什么：把 project-config 里依赖项目形状的槽位（桶规则、配对规则、验证命令、L / M 路径）抽成三四套预设：Python 单包 / 前端 / monorepo / 纯文档；接入时选一套再微调。
为什么：路由器隐含假设是 Python 单包 + git + pytest + `scripts/` 配 `tests/`，换形状就全错。
判据：G1 的仓库能从预设选一套，微调不超过 5 个槽位。
依赖：G1 撞出真实差异后再定预设内容，不凭空写。

**G3 接入成本压到十分钟。**（#9）
做什么：定义「最小可用配置」（≤ 5 个必填，其余带默认）；加一个初始化命令，生成配置骨架和指令片段，并报告「你还缺哪几个」。
为什么：五十个槽位没人会填。
判据：C1 的十分钟；初始化命令有自测和正式测试，登记进 checks.md。

**G4 规则有程序层的手。**（#10）
做什么：提供 hook 模板（任务开始注入「先跑路由器」；工具调用前拦红线：force push、改可见性、删跟踪文件；收尾前核交付单三栏），至少覆盖 Claude Code 的 hook 机制；对话交付（不开 PR）也能被拦。
为什么：现在的检查只在 PR 事件上生效，对话里交付全靠自觉。
判据：C4；hook 各带「它会响」证明；误报预算进 checks.md。
边界：hook 只拦红线和格式，不替人判断。

**G5 骨架与复制品的同步检查。**（#11）
做什么：接入片段（core/01 §0 与各项目的指令文件）、档位矩阵（core/01 §4 与路由器代码）做成一份生成另一份，或加一道对账检查。
为什么：两份真值现在靠人记着同步；一旦分叉，接入项目读到的规则就不是骨架的规则。
判据：对账检查登记进 checks.md，WARN 试用；故意改一处能响。

### 应该（成熟之后很快会疼）

**G6 版本与升级路径。**（#12）
做什么：core 打版本号；槽位增删的兼容规则；一道「你的配置比骨架旧」检查；升级说明。
判据：G1 的仓库经历过一次骨架升级不炸。

**G7 台账跑完一个周期。**（#13）
做什么：第一次里程碑交接真跑 `metrics_report`，处置退役候选，按台账调一次 `tier.s_limits`。
判据：C3；调整理由写进 project-config 说明列。

**G8 三个是非题的兜底。**（#14）
做什么：H1–H3 自答之外加一道独立复核（异模型或第二人），只在 L 档或 diff 反查报 ⚠ 时触发。
判据：至少一次复核推翻或确认过一个自答，记录在 observations。
边界：复核只能升档不能降档，与「只升不降」同源。

**G9 真实案例进骨架。**（#15）
做什么：把本仓 PR #2（M 档、撞出两处 bug）、PR #3（L 档、用户确认删除）整理成 `core/examples/` 的两个真实案例；再补一个 S 档真实小任务。
判据：三个案例各能被 `lint_pr_body` 核过。

**G10 跨平台 CI。**（#16）
做什么：CI 加 Windows 任务；编码与路径的坑表条目对应测试在两个平台都跑。
判据：两平台同时绿。

### 锦上添花

**G11 术语表与英文入口。**（#18） 刹车、DoD、goal、节点、里程碑一页术语表；README 英文摘要。判据：非中文读者能按 README 完成 G3 的十分钟接入。

**G12 公开与许可。**（#19） 内部材料清零（PR #3）后重估公开；加 LICENSE 与贡献指南；届时改红线「不设 public」为「不带内部材料」。判据：用户裁定。

**G13 第二双眼睛。**（#20） 请原评审再看一轮 S1 落地后的骨架。判据：C5。

## 4. 不做的事

- 不重写骨架的核心语义（三态、三栏、路由卡、只升不降）—— 除非 G1 撞出来。
- 不加新的流程步骤。S2 的方向是**减**接入成本，不是加规则。
- 不在本仓里模拟接入。每一条判据都要在真项目上核。
