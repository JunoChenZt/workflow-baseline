# docs/archive — 阶段归档

> 2026-09-28 立（S2 收口 G2·backlog O 任务 1）。规则的**执行时点**写在 [08-retro-node-and-pr.md §2.11.10](../governance/workflow/08-retro-node-and-pr.md#21110-阶段收口时的归档2026-09-28-立)，本页讲**归档是什么、怎么做**。

## 大白话

一个阶段做完了，它留下的计划、复盘、跑批记录还在原来的文件夹里，和下一阶段的新东西混在一起。归档要做的是**给这一阶段立一本目录**：翻开就知道这阶段产出了哪些文件、各在哪、哪些已经封存不再改。

**文件本身不搬家。** 仓库里文档之间光是指向其他 `.md` 的链接就有两千八百多处（2026-09-28 粗数），搬一个文件就要改一串链接，改漏了就是断链。所以「归档」= 在这里写一页索引、给原文件定性，而不是把文件挪进这个文件夹。

## 1. 归档什么

每个阶段收口时，在本目录建一页 `<阶段>.md`（如 `S2.md`），按下表逐类列出：

| 类别 | 通常在哪 | 索引里写什么 |
|---|---|---|
| 阶段真值源 | `docs/roadmap/<阶段>.md` | 链接 + 「本阶段已收口」的日期 |
| 交接 / 收口报告 | `docs/observations/*verification-report*`、收口报告 | 逐份链接 + 结论一句话 |
| 节点复盘 | `docs/retro/<阶段>/` | 目录链接 + 份数（按目录整体引用即可，不必逐份列） |
| 节点拆解 / 计划 | `docs/plans/` | 属于本阶段的逐份链接（`plans/` 不按阶段分目录，只能在这里列） |
| 跑批与观测证据 | `docs/observations/` | 只列**承重**的（被收口报告、交接报告、backlog close 引用过的）；其余按「日期落在本阶段起止之间」即可定位，不逐份列 |
| 移交下一阶段的清单 | 收口报告内，并同步写进下一阶段 roadmap | 两处都链上 |

## 2. 归档后的文件怎么对待

归档**不新增冻结规则**，只是把已有规则对号入座，在索引里给每类标清楚：

- **节点复盘 / 已冻结的判定档 / 已关闭的 backlog 条目** → 按 [刹车自检 Q6](../governance/workflow/05-brake-self-check.md) 冻结，**一个字都不改**，包括导航链接和错别字；需要补的前向事实写在引用方。
- **其余历史文档**（计划、观测记录、阶段真值源）→ 按 CLAUDE.md R7：正文不改，有状态变化时在顶部加前向说明。
- **本目录下的索引页本身**可以随时补充（它是导航，不是历史记录）。

## 3. 什么时候才搬文件

默认**不搬**。只有某个目录大到妨碍日常使用、且用户明确裁定时才搬，而且必须同一个 PR 里做完三件事：

1. `git mv` 搬文件；
2. 全仓改写指向它们的链接；
3. 跑 [scripts/lint_doc_links.py](../../scripts/lint_doc_links.py) 全绿再合。

## 4. 下一阶段怎么起步，能让以后归档更省事

- 节点复盘继续按阶段分目录：`docs/retro/<阶段>/`。
- 新阶段的计划文件名里带阶段号（如 `S3-…-decomposition-….md`），以后在 `plans/` 里按前缀就能认出归属。
